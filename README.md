## 🎯 این پروژه چیست؟

یک دفترچه‌ی دیجیتال که هر روز در آن ثبت می‌کنی چه کرده‌ای — و برخلاف اپ‌های
مشابه، **فقط چیزی را می‌پرسد که واقعاً استفاده می‌کنی**.

چهار بخش دارد که هرکدام را جدا روشن یا خاموش می‌کنی:

<div align="center">

| ماژول | برای چه کسی | چه ثبت می‌کند |
|:---:|---|---|
| 🏃 **ورزش** | دونده، پیاده‌رو، فوتسالیست | دویدن، پیاده‌روی، فوتسال، هدف هفتگی |
| 🏋️ **باشگاه** | آمادگی جسمانی یا بدنسازی | جلسات به‌صورت «بلوک»، سختی، درد |
| 📚 **مطالعه** | دانش‌آموز و دانشجو | مدت، درس، تمرکز، درصد تست |
| 😴 **خواب و انرژی** | همه — مشترک بین سه ماژول بالا | ساعت خواب و بیداری، چرت، انرژی |

</div>

بعد اپ خودش نمودار می‌کشد، الگو پیدا می‌کند، و به زبان ساده می‌گوید امروز
بدنت آماده‌ی تمرین سنگین هست یا بهتر است سبک بگیری.

> **همه‌چیز مال خودت است.** داده اول روی همان گوشی یا لپ‌تاپ ذخیره می‌شود، و
> اگر خودت بخواهی با یک GitHub Gist **خصوصی که مالکش تویی** سینک می‌شود.
> نه سروری در کار است، نه ثبت‌نامی، نه ترکری.

</div>

## 🧩 چهار ماژول مستقل

</div>

<div align="center">

```
⚙️ تنظیمات › 🎛️ بخش‌های فعال

  🏃 ورزش و پیاده‌روی      [●━━]  روشن
  🏋️ باشگاه                [━━○]  خاموش
  📚 مطالعه                [━━○]  خاموش
  😴 خواب و انرژی          [●━━]  روشن   ← مشترک بین همه

**چند نمونه‌ی واقعی:**

| کاربر | ورزش | باشگاه | مطالعه | نتیجه |

- 🔒 داده‌ی هر ماژول **کاملاً جدا** ذخیره می‌شود — هیچ‌کدام روی آمار دیگری اثر ندارد

- 📱 نوار پایین هیچ‌وقت بیشتر از **۵ تب** نمی‌شود؛ بقیه به شیت «⋯ بیشتر» می‌روند

## 🚀 شروع سریع

**راحت‌ترین راه:** روی [این لینک](https://abbasahmadizade.github.io/my-sport-reports-only/)
بزن، یک رمز بساز، تمام. هیچ نصبی لازم نیست.

**می‌خواهی نسخه‌ی خودت را داشته باشی؟** چهار قدم:

</div>

<div dir="rtl" align="right">

### ۱️⃣ Fork بزن

بالای همین صفحه دکمه‌ی **Fork** را بزن تا یک کپی در اکانت خودت ساخته شود.

### ۲️⃣ GitHub Pages را روشن کن

`Settings` ← از منوی چپ `Pages` ← زیر **Source** گزینه‌ی `Deploy from a branch`
← برنچ `main` و پوشه‌ی `/ (root)` ← **Save**

### ۳️⃣ یکی دو دقیقه صبر کن

آدرست به این شکل آماده می‌شود:

</div>

<div dir="ltr" align="left">

```
https://<your-username>.github.io/my-sport-reports-only/
```

</div>

<div dir="rtl" align="right">

### ۴️⃣ رمز بساز

اولین بار نام کاربری و رمز می‌خواهد. این رمز **فقط روی همین دستگاه** ذخیره
می‌شود و هیچ‌جا فرستاده نمی‌شود.

> 💡 **رمزت یادت رفت؟** بخش [عیب‌یابی](#troubleshooting) — داده‌ات از بین نمی‌رود.

> 🔄 **نسخه‌ی جدید را نمی‌بینی؟** آدرس را با یک پارامتر باز کن: `?v=662`

</div>

## ☁️ راه‌اندازی سینک ابری

بدون این هم اپ کامل کار می‌کند — داده روی همان مرورگر می‌ماند. ولی اگر
می‌خواهی بین گوشی و لپ‌تاپ سینک شود، یا نگران پاک‌شدن مرورگر هستی، حدود
**۳ دقیقه** وقت می‌گیرد.

> 🧭 **راهنمای قدم‌به‌قدم داخل خود اپ هم هست:**
> ⚙️ ← «🔑 تنظیمات» ← بالای پنجره: **«اولین بار است؟ راهنمای قدم‌به‌قدم»**
> با لینک مستقیم به هر صفحه.

### ۱️⃣ یک Gist خصوصی بساز

به [gist.github.com](https://gist.github.com) برو:

| فیلد | مقدار |
|---|---|
| نام فایل | `sport-data.json` |
| محتوا | `{"init":true}` |
| نوع | **Create secret gist** (نه Public) |

### ۲️⃣ Gist ID را بردار

بعد از ساختن، به نوار آدرس نگاه کن:

</div>

<div dir="ltr" align="left">

```
https://gist.github.com/username/a1b2c3d4e5f6a7b8c9d0
                                  └──────────────────┘
                                    این همان Gist ID است
```

</div>

<div dir="rtl" align="right">

### ۳️⃣ یک Token بساز

به [github.com/settings/tokens/new](https://github.com/settings/tokens/new) برو:

- یک نام دلخواه بنویس، مثل `sport-report`
- انقضا: هرچه طولانی‌تر بهتر
- از لیست تیک‌ها **فقط** `gist` را بزن — نه `repo`، نه چیز دیگر
- **Generate token** و **همان لحظه کپی کن** (گیت‌هاب فقط یک‌بار نشانش می‌دهد)

### ۴️⃣ در اپ واردشان کن

⚙️ ← «🔑 تنظیمات» ← Token و Gist ID را بگذار ← **💾 ذخیره**

### ۵️⃣ تست بگیر

دکمه‌ی **🔎 بررسی Gist** را بزن. باید چیزی شبیه این ببینی:

</div>

<div dir="ltr" align="left">

```
✅ Gist قابل خواندن است

روزهای ورزش: ابر 42 / محلی 42
جلسات باشگاه: ابر 12 / محلی 12
بخش‌های فعال روی ابر: ورزش، باشگاه، خواب
فایل دستگاه‌ها: 2
بکاپ محافظ: موجود ✅
```

</div>

<div dir="rtl" align="right">

### ۶️⃣ دستگاه دوم

روی گوشی یا لپ‌تاپ دوم، **همان Token و همان Gist ID** را وارد کن. اپ خودش
داده‌ی دو طرف را تلفیق می‌کند — هیچ‌چیز پاک نمی‌شود.

</div>

<a id="safety"></a>

## 🛡️ داده چطور محافظت می‌شود؟

این مهم‌ترین بخش پروژه است. منطق سینک طوری نوشته شده که **هیچ سناریویی
منجر به از‌دست‌رفتن داده نشود**.

### چرخه‌ی سینک

</div>

<div dir="ltr" align="center">

```
   ┌──────────┐     ┌───────────┐     ┌──────────┐     ┌─────────┐
   │   PULL   │────▶│   MERGE   │────▶│   PUSH   │────▶│ VERIFY  │
   │ خواندن   │     │  تلفیق    │     │  نوشتن   │     │  تأیید  │
   └──────────┘     └───────────┘     └──────────┘     └─────────┘
        │                 │                 │               │
   وضعیت ابر        جدیدترین نسخه‌ی      فقط اگر        دوباره خواند
   خوانده می‌شود    هر رکورد برنده        تغییری         و مقایسه کرد
                    می‌شود                باشد
```

</div>

<div dir="rtl" align="right">

### چهار لایه‌ی محافظت

| لایه | چه می‌کند |
|---|---|
| **۱. نسخه‌ی هر رکورد** | هر رکورد یک `_updatedAt` دارد؛ در تلفیق، جدیدترین برنده است |
| **۲. فایل جدا برای هر دستگاه** | گوشی و لپ‌تاپ روی هم نمی‌نویسند |
| **۳. Tombstone برای حذف** | حذف روی یک دستگاه، با سینک از دستگاه دیگر برنمی‌گردد |
| **۴. بکاپ قبل از اولین نوشتن** | یک snapshot تغییرناپذیر از کل Gist، با هش SHA-256 |

### تضمین‌های تست‌شده

هرکدام از این‌ها یک تست خودکار دارد که با هر تغییر اجرا می‌شود:

- ✅ داده‌ی قدیمی هرگز پاک نمی‌شود — با ۶۰ روز داده‌ی واقعی تست شده
- ✅ فیلدهای جدید روی رکوردهای قدیمی **خالی** می‌مانند، نه صفر
- ✅ فایل خراب روی Gist، داده‌ی محلی را **پاک نمی‌کند**
- ✅ فایل‌های نامرتبط در Gist دست نمی‌خورند
- ✅ Token هیچ‌جا در DOM یا لاگ ظاهر نمی‌شود

### فایل‌هایی که در Gist ساخته می‌شوند

| فایل | نقش |
|---|---|
| `sport-data.json` | داده‌ی اصلی تلفیق‌شده |
| `sport-device-<id>.json` | نسخه‌ی مستقل هر دستگاه |
| `sport-migration-backup-v56.json` | بکاپ محافظ قبل از اولین نوشتن |
| `sport-local-before-v56-<id>.json` | کپی داده‌ی محلی قبل از اولین تلفیق |
| `sport-snapshot-<timestamp>.json` | snapshot دستی، هر وقت خودت بخواهی |

### مصرف API گیت‌هاب

سقف گیت‌هاب **۵۰۰۰ درخواست در ساعت** است. مصرف واقعی این اپ:

| عملیات | تعداد درخواست |
|---|:---:|
| سینک بدون تغییر | ۱ |
| سینک با تغییر | ۳ |
| اولین اتصال (با بکاپ) | ۵ |
| بررسی خودکار هر ۱۵ دقیقه | ۴ در ساعت |

> 💡 اگر سهمیه کم شود، اپ خودش سینک خودکار را موقتاً متوقف می‌کند.

| ۷ | 🕸️ رادار | رادار | سه هفته‌ی آخر روی پنج محور (کم‌رنگ = قدیمی‌تر) |

- **📥:** خروجی PNG

## 🗺️ نقشه فعالیت

چیدمان تقویمی: **هر سطر یک هفته، هر ستون یک روز هفته** — بدون اسکرول افقی.

</div>

<div dir="ltr" align="center">

```
                 ج   پ   چ   س   د   ی   ش
        ─────────────────────────────────────── مرداد ۱۴۰۵
   3/5   9   8   7   6   5   4   3
  10/5  16  15  14  13  12  11  10
  17/5          ⌷20  19  18  17     ← ⌷ = امروز

        کم  ·  ░  ▒  ▓  █  ·  زیاد        ┆ خط‌چین = ثبت‌نشده
```

</div>

<div dir="rtl" align="right">

**امتیاز هر خانه (حداکثر ۱۰۰):**

| شرط | امتیاز |
|---|:---:|
| روز تمرین بوده | **۴۰+** |
| مجموع تمرین نسبت به هدف روزانه | **۰ تا ۲۵+** |
| کیفیت خواب — نزدیکی به هدف | **۰ تا ۲۰+** |
| انرژی ÷ ۱۰ × ۱۵ | **۰ تا ۱۵+** |

**با یک نگاه معلوم است:**

| نشانه | یعنی |
|---|---|
| خانه‌ی پُر با عدد سفید | ثبت شده، امتیاز بالا |
| خانه‌ی کم‌رنگ | ثبت شده ولی تمرینی نبوده |
| خانه‌ی **خط‌چین** | اصلاً ثبت نشده |
| حلقه‌ی بنفش | امروز |
| نقطه‌ی زرد | آن روز فوتسال بوده |

**تعامل:** ضربه‌ی اول خلاصه، ضربه‌ی دوم همان روز را در بخش ثبت باز می‌کند.
روی روز خالی، مستقیم فرم ثبت **همان تاریخ** باز می‌شود.

## 🏋️ ماژول باشگاه

برخلاف اپ‌های بدنسازی که اول از تو می‌پرسند «چه حرکتی زدی؟»، این ماژول
**بلوک‌محور** است. دلیلش ساده است: خیلی‌ها می‌روند باشگاه، ۲۰ دقیقه تردمیل
می‌دوند، ۲۰ دقیقه با وزنه روی دوچرخه کار می‌کنند و بعد یک بخش سخت انجام
می‌دهند که **اسمش را نمی‌دانند** و هر جلسه هم فرق می‌کند. اجبار به نوشتن نام
حرکت یعنی آن آدم بعد از سه جلسه ثبت را رها می‌کند.

### چهار نوع بلوک

| نوع | برای چه | چه می‌پرسد |
|:---:|---|---|
| 🏃 **هوازی** | تردمیل، دوچرخه، الپتیکال، طناب | مدت + سرعت/سطح *(اختیاری)* |
| 🔄 **ترکیبی** | حرکت همراه با وزنه، مثل دوچرخه + دمبل | مدت + وزن هر دست |
| 🤸 **آزاد** | حرکاتی که اسمشان را نمی‌دانی | مدت + سختی + توضیح *(اختیاری)* |
| 🏋️ **دستگاه/ست** | بدنسازی کلاسیک | حرکت + ست/تکرار/وزن |

</div>

<div align="center">

```
یک جلسه‌ی معمولی آمادگی جسمانی:

  🏃 تردمیل ............... ۱۸ دقیقه
  🔄 دوچرخه + وزنه ........ ۲۰ دقیقه · ۱kg هر دست
  🤸 حرکات آزاد ........... ۱۵ دقیقه · سختی ۹
  ─────────────────────────────────────────────
  🔥 سختی کل: ۹/۱۰      😣 درد: متوسط (زانو)
```

</div>

<div dir="rtl" align="right">

### دو عددی که واقعاً مهم‌اند

برای کسی که تازه شروع کرده، **وزنه** مهم‌ترین عدد نیست. این دو تا هستند:

- **🔥 سختی (۰-۱۰)** — جواب صادقانه به «چقدر سخت بود؟»
- **😣 درد (نداشتم / کم / متوسط / زیاد + محل)** — با روند خودکار

بعد از چند هفته اپ می‌گوید: *«درد در ۵ جلسه ثبت شده (بیشتر زانو) و روندش رو
به کاهش است — بدنت دارد عادت می‌کند.»*

### ⭕️ ثبت روزی که نرفتی

این مهم‌تر از چیزی است که به نظر می‌رسد. با یک ضربه و ۹ دلیل آماده:

😴 خسته بودم · 💼 کار/درس · 🤕 بدن‌درد · 🤒 مریض بودم · 🚌 نرسیدم بروم
· 📱 حسش نبود · 🚪 باشگاه تعطیل بود · ❤️ ریکاوری عمدی · ❓ سایر

بعد از چند هفته: *«۴ جلسه از دست رفت — بیشترین دلیل: کار/درس (۳ بار)»* — که
یعنی مشکل تنبلی نیست، **برنامه‌ات با کلاس‌هایت جور نیست**.

> ✅ روزهای نرفته **میانگین‌ها را خراب نمی‌کنند**. اگر دو جلسه‌ی ۵۰ دقیقه‌ای
> داشته‌ای و یک روز نرفته‌ای، میانگینت همان ۵۰ می‌ماند، نه ۳۳.

### سرعت ثبت

دکمه‌ی **«🔁 مثل جلسه‌ی قبل»** کل ساختار جلسه‌ی قبلی را برمی‌گرداند — فقط
عددهایی که فرق کرده‌اند را عوض می‌کنی. **حدود ۲۰ ثانیه.**

### تحلیل‌ها

روند سختی · روند درد · ترکیب جلسات (هوازی/ترکیبی/آزاد) · خواب → سختی درک‌شده
· افت انرژی · رکورد هر حرکت<sup>*</sup> · حجم تمرین<sup>*</sup>

<sub><sup>*</sup> فقط وقتی بلوک «دستگاه/ست» ثبت شده باشد — صفحه‌ی کسی که
هوازی کار می‌کند شلوغ نمی‌شود.</sub>

<a id="security"></a>

## 🔒 امنیت

| لایه | جزئیات |
|---|---|
| **Content-Security-Policy** | `default-src 'none'` + هش SHA-256 برای تک‌تک اسکریپت‌ها · `object-src 'none'` · `base-uri 'none'` |
| **بدون inline handler** | هیچ `onclick` یا `onerror` در HTML نیست — همه با `addEventListener` |
| **ضد XSS** | تمام ورودی‌های کاربر قبل از نمایش escape می‌شوند |
| **رمز عبور** | PBKDF2-SHA256 با ۲۱۰٬۰۰۰ تکرار و salt تصادفی · هرگز خام ذخیره نمی‌شود |
| **محدودیت تلاش** | بعد از ۵ تلاش ناموفق، قفل موقت تصاعدی |
| **CSV امن** | سلول‌هایی که با `=` `+` `-` `@` شروع شوند خنثی می‌شوند |
| **دامنه‌های مجاز** | فقط `api.github.com` و `gist.githubusercontent.com` |
| **توکن** | فقط در `localStorage` مرورگر خودت · در DOM ظاهر نمی‌شود · هیچ‌جا لاگ نمی‌شود |

> ⚠️ **حواست باشد:** این اپ برای **استفاده‌ی شخصی** ساخته شده. رمز عبور جلوی
> چشم فضول را می‌گیرد، ولی کسی که دسترسی فیزیکی به دستگاهت داشته باشد
> می‌تواند `localStorage` را بخواند. برای داده‌ی واقعاً حساس استفاده نکن.

  modules: { sport: true, gym: false, study: false, sleep: true },

  // ── sport: one row per day ──
  rows: [{
    id:            number,
    jdate:         string,     // "1405-05-10"
    completed:     boolean,
    energy:        number,     // 0-10   (0 = not recorded)
    mood:          number,     // 0-10
    runMin:        number,     // decimal: 1.17 = 1 min 10 sec
    walkMin:       number,     // deliberate sport walking
    walkDailyMin:  number,     // commuting — never counts as training
    longestRun:    number,
    missReason:    string,     // sleep|work|sick|weather|lazy|recovery|other
    trainHour:     number|null,
    activity:      string,
    note:          string,
    futsalRef:     boolean,
    sleepBlocks:   [{ label, start: "23:30", end: "07:15" }],  // main + extras;
                               // classified by TIME, not by the label text
    officialWake:  string|null,
    _updatedAt:    number      // drives cross-device merge
  }],

  // ── gym: block-based, not exercise-based ──
  gym: [{
    id, jdate,
    missed:        boolean,    // "I was meant to go and didn't"
    missReason:    string,     // tired|busy|sore|sick|far|mood|closed|rest|other
    durationMin:   number,
    hardness:      number,     // 0-10, self-reported
    painLevel:     number,     // 0=none 1=mild 2=moderate 3=severe
    painWhere:     string[],   // knee|thigh|back|shoulder|...
    supplements:   string[],
    blocks: [
      { t: 'cardio', name: 'تردمیل', min: 18, level: 6 },
      { t: 'combo',  name: 'دوچرخه + وزنه', min: 20, w: 1, wPer: 'hand' },
      { t: 'free',   min: 15, hard: 9, desc: '' },
      { t: 'sets',   name: 'پرس سینه', g: 'chest',
                     sets: [{ w: 40, r: 12 }, { w: 45, r: 10 }] }
    ],
    _updatedAt
  }],
  gymBody: [{ id, jdate, weight, note, _updatedAt }],

  // ── study: multiple sessions per day ──
  study: [{
    id, jdate, subject, topic, minutes, start, end, method,
    focus, difficulty, satisfaction, distractions,
    questions, correct, note, _updatedAt
  }],

  futsal: [{ id, jdate, energyBefore, energyAfter,
             durationActual, intensity, _updatedAt }],

  goals:       { sleepGoalHours, activityGoalMin,
                 weeklyTargetMode, weeklyTargetDays, preferredTime },
  gymConfig:   { enabled, weeklyGoal, weekDays, showSupplements,
                 countsAsTraining },
  studyConfig: { enabled, dailyGoalMin, subjects, showSleepInReport },
  programGoal: string,

  _sync: {
    rowsDeleted:    { [id]: revision },   // tombstones
    futsalDeleted:  { [id]: revision },
    studyDeleted:   { [id]: revision },
    gymDeleted:     { [id]: revision },
    gymBodyDeleted: { [id]: revision },
    fields: { goals, programGoal, study, gym, modules }
  }
}
```

</div>

<div dir="rtl" align="right">

> ⚠️ `runMin` اعشاری است و `formatMin()` تبدیلش می‌کند به `mm:ss`.
> `_updatedAt` قلب سیستم تلفیق است — دست‌کاری‌اش نکن مگر دقیقاً بدانی چه می‌کنی.

## 🔧 عیب‌یابی

<details>
<summary><b>🔑 رمزم یادم رفته</b></summary>

<br>

از داخل خود اپ: ⚙️ ← **🔑 تغییر رمز** ← کلمه‌ی `RESET` را بنویس.

یا از کنسول مرورگر (`F12` روی دسکتاپ):

<div dir="ltr" align="left">

```javascript
localStorage.removeItem('sport_auth_v1');
localStorage.removeItem('sport_session_v1');
location.reload();
```

</div>

فقط قفل پاک می‌شود و **داده‌ات دست نمی‌خورد**.

</details>

<details>
<summary><b>🏋️ بخش باشگاه یا مطالعه را پیدا نمی‌کنم</b></summary>

<br>

هر دو پیش‌فرض **خاموش**‌اند. دو راه برای روشن‌کردن:

۱. **سریع:** ⚙️ ← زیر «🎛️ بخش‌های فعال» سوییچ را بزن
۲. **کامل:** ⚙️ ← «تنظیمات کامل» ← کارت «🎛️ بخش‌های فعال»

بعد از روشن‌کردن، تب مربوطه پایین صفحه ظاهر می‌شود. اگر بخش‌های زیادی روشن
باشند، تب‌های اضافه به شیت **«⋯ بیشتر»** می‌روند.

</details>

<details>
<summary><b>☁️ سینک کار نمی‌کند</b></summary>

<br>

به ترتیب چک کن:

۱. **🔎 بررسی Gist** را بزن و متن خطا را بخوان
۲. توکن scope `gist` دارد؟ نه `repo`، نه چیز دیگر — فقط `gist`
۳. Gist ID درست است؟ فقط همان رشته‌ی هگز، بدون نام کاربری و اسلش
۴. توکن منقضی نشده؟ از [صفحه‌ی Tokens](https://github.com/settings/tokens) چک کن
۵. اگر نوشته سهمیه تمام شده، تا شروع ساعت بعد صبر کن

</details>

<details>
<summary><b>📉 انگار یک رکورد گم شده</b></summary>

<br>

نفس عمیق بکش، تقریباً همیشه سالم است:

۱. به Gist خودت در [gist.github.com](https://gist.github.com) برو
۲. فایل‌های `sport-migration-backup-*.json` یا `sport-device-*.json` را باز کن
۳. محتوا را کپی کن و در اپ از بخش **📥 وارد کردن** برگردان
۴. خود Gist هم تب **Revisions** دارد — تاریخچه‌ی کامل همه‌ی تغییرها آنجاست

</details>

<details>
<summary><b>🔄 نسخه‌ی جدید را نمی‌بینم</b></summary>

<br>

کش مرورگر است. یکی از این‌ها را امتحان کن:

- آدرس را با یک پارامتر باز کن: `?v=662`
- روی دسکتاپ `Ctrl+Shift+R`
- روی اندروید: تنظیمات کروم ← حریم خصوصی ← پاک‌کردن داده‌های مرور ← فقط
  «تصاویر و فایل‌های ذخیره‌شده»

</details>

<details>
<summary><b>🩺 چطور از سلامت اپ مطمئن شوم</b></summary>

<br>

⚙️ ← **🩺 تست سلامت** — گزارش کامل نسخه، داده، ماژول‌های فعال، سینک و بکاپ.

یا از کنسول:

<div dir="ltr" align="left">

```javascript
window._app.runHealthCheck()                    // full report
console.log(window._app.state().rows.length)    // sport days
console.log(window._app.state().gym.length)     // gym sessions
console.log(window._app.state().modules)        // which modules are on
```

</div>

</details>

<details>
<summary><b>⭕️ روزی که نرفتم را چطور ثبت کنم</b></summary>

<br>

**در باشگاه:** دکمه‌ی **«⭕️ امروز نرفتم»** در صفحه‌ی باشگاه، یا داخل فرم
دکمه‌ی **«⭕️ نرفتم»**. بعد یکی از ۹ دلیل آماده را بزن (اختیاری).

**در ورزش:** روز را ثبت کن و «انجام نشد» بگذار؛ فیلد «چرا نرفتم» ظاهر می‌شود.

روزهای نرفته **میانگین‌ها را خراب نمی‌کنند** — جدا شمرده می‌شوند و فقط در
تحلیلِ «چه چیزی جلوی رفتنت را می‌گیرد» استفاده می‌شوند.

</details>

**🐞 باگ جدی در بلوک‌های خواب**

بلوک‌های خواب بر اساس **نام** دسته‌بندی می‌شدند و کد فقط «چرت» و `nap` را
می‌شناخت. هر اسم دیگری — «خواب بعدازظهر»، «خواب دوم»، «استراحت ظهر»،
«قیلوله» — به‌اشتباه **خواب شب** حساب می‌شد.

نتیجه‌اش این بود که ساعت بیداری به‌جای `06:45` می‌شد `15:20`، و این عدد غلط
وارد نمودار ساعت خواب، تحلیل ریتم، پیش‌پرکردن فرم باشگاه و همه‌ی گزارش‌ها
می‌شد.

**حالا دسته‌بندی بر اساس زمان است، نه اسم:**
- خواب اصلی = بلندترین بلوکی که در بازه‌ی شب (۱۸:۰۰ تا ۱۱:۵۹) شروع شود
- بقیه = خواب دوم، با هر اسمی که خودت گذاشته باشی
- کارگر شیفت شب هم پشتیبانی می‌شود (اگر هیچ بلوکی در بازه‌ی شب نباشد)
- خواب چندتکه: بلندترین بلوک شب، خواب اصلی است

**🕐 نام و ساعت دقیق در همه‌ی خروجی‌ها**
- قبلاً فقط مجموع دقیقه زیر برچسب «چرت» می‌آمد
- حالا: `خواب بعدازظهر 14:00-15:20` — با نام واقعی و ساعت شروع و پایان
- در خروجی AI (هر چهار حالت) و گزارش‌های چاپی
- خلاصه هم می‌گوید کاربر از چه عنوان‌هایی استفاده می‌کند

**🧠 تحلیل جدید: آیا امروز به خواب روز نیاز دارم؟**
- **رابطه‌ی شب کوتاه ← خواب روز:** «روزهایی که خواب دوم داشتی، شب قبلش
  به‌طور میانگین ۲:۴۵ کمتر خوابیده بودی»
- **اثر خواب روز روی شب بعد:** «بعد از خواب‌های روزِ بلند (۴۵ دقیقه به بالا)،
  شب بعدش حدود ۳۵ دقیقه کمتر خوابیدی»
- جایگزین تحلیل قبلی که فقط تعداد چرت‌ها را می‌شمرد

**🐞 رفع باگ دیگر**

## 🇬🇧 In English

**Sport Report** is a single-file personal tracker for exercise, gym, study
and sleep, built around the Persian (Jalali) calendar.

The entire application lives in one `index.html` — no build step, no npm, no
backend, no framework. Chart.js and the Jalali date library are embedded
directly in the file, so it runs fully offline. Data is stored locally in your
browser and can optionally sync to a **private GitHub Gist that you own**,
using your own token, with no third-party server in between.

### Four independent modules

Each one is a separate switch; all 8 combinations are tested.

| Module | For whom | Tracks |
|---|---|---|
| 🏃 **Sport** | Runners, walkers | Running, walking, futsal, weekly target |
| 🏋️ **Gym** | Conditioning or bodybuilding | Block-based sessions, perceived hardness, pain |
| 📚 **Study** | Students | Duration, subject, focus, test accuracy |
| 😴 **Sleep** | Everyone — shared across the above | Bed/wake times, naps, energy |

The gym module is deliberately **block-based rather than exercise-based**:
many people do "20 min treadmill + 20 min bike-with-weights + whatever the
coach shouts out" and genuinely do not know the movement names. Forcing an
exercise name on them means they simply stop logging.

### Highlights

| | |
|---|---|
| 🗓️ | Native Jalali calendar with correct leap-year handling |
| 😴 | Multi-block sleep tracking — naps and split sleep fully supported |
| 📊 | 8 interactive charts with 14 / 30 / 90 / all-time ranges |
| 🔁 | Momentum score instead of streaks — one rest day does not reset progress |
| 🧠 | Readiness score weighted by data freshness, with a confidence rating |
| 📤 | AI-ready exports with a dedicated prompt per module, in three sizes |
| ☁️ | Conflict-safe sync — pull, merge, push, verify — with per-device shards, deletion tombstones and automatic pre-write backups |
| 🔒 | Strict CSP with per-script hashes, zero inline handlers, PBKDF2-SHA256 at 210k iterations |
| 📱 | Mobile-first RTL interface, responsive from 320px |
| 🧪 | 1199 automated tests running in a real browser at real phone sizes |

**Try it:** [abbasahmadizade.github.io/my-sport-reports-only](https://abbasahmadizade.github.io/my-sport-reports-only/)

Fork it, enable GitHub Pages on `main` / root, and it is live. The interface
is entirely in Persian.

Built with AI assistance on [**Arena.ai**](https://arena.ai) — huge thanks to
their team for making solo projects like this genuinely possible. 💜
