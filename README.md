- چقدر **خوابیدی** — چندتیکه هم باشه مشکلی نیست، چرت بعدازظهر هم حساب می‌شه

## ☁️ راه‌اندازی سینک ابری

اختیاریه، ولی اگه می‌خوای دیتات بین گوشی و لپ‌تاپ سینک بشه و با گم شدن گوشی از بین نره، حتماً انجامش بده. حدود دو دقیقه وقت می‌بره.

### ۱. یک Gist خصوصی بساز

برو به [gist.github.com](https://gist.github.com) و این‌طوری پرش کن:

| فیلد | مقدار |
|---|---|
| نام فایل | `sport-data.json` |
| محتوا | `{}` |
| نوع | حتماً **Create secret gist** |

بعد از ساخته شدن، **Gist ID** رو از نوار آدرس بردار — همون رشته‌ی طولانی آخر آدرس:

</div>

<div dir="ltr" align="left">

```
https://gist.github.com/your-username/a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6
                                      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                                  Gist ID
```

</div>

<div dir="rtl" align="right">

### ۲. یک Token بساز

برو به [این صفحه](https://github.com/settings/tokens/new?scopes=gist&description=Sport%20Report%20Sync) — تنظیماتش از قبل آماده‌ست:

- **Note:** یه اسم دلخواه، مثلاً `Sport Report Sync`
- **Expiration:** `No expiration` یا هر مدتی که راحتی
- **Scopes:** فقط و فقط تیک `gist` ✅ — هیچ گزینه‌ی دیگه‌ای رو تیک نزن

دکمه‌ی **Generate token** رو بزن و توکن رو کپی کن.

> ⚠️ **این توکن فقط یک بار نشون داده می‌شه.** قبل از بستن صفحه یه جای امن ذخیره‌ش کن. اگه گم شد مشکلی نیست — از همون [صفحه‌ی Tokens](https://github.com/settings/tokens) حذفش کن و یکی جدید بساز.

### ۳. توی اپ واردشون کن

توی اپ برو به **⚙️ تنظیمات** ← بخش **☁️ همگام‌سازی ابری** ← توکن و Gist ID رو بچسبون ← **ذخیره**.

### ۴. تست بگیر

دکمه‌ی **🔌 تست اتصال GitHub** رو بزن. باید چیزی شبیه این ببینی:

</div>

<div dir="ltr" align="left">

```
✅  Token valid
✅  Gist read access
✅  sport-data.json  found
✅  protection backup  found
```

</div>

<div dir="rtl" align="right">

### ۵. دستگاه دوم

روی گوشی یا لپ‌تاپ دوم همون آدرس رو باز کن و **همون توکن و همون Gist ID** رو وارد کن. دیتا خودش میاد پایین و با دیتای محلی تلفیق می‌شه.

> 🔒 **توکنت رو هیچ‌وقت commit نکن.** توکن فقط داخل `localStorage` مرورگر خودت می‌مونه و توی هیچ فایلی از این ریپازیتوری نوشته نمی‌شه.

## 🛡️ دیتا چطور محافظت می‌شه؟

بزرگ‌ترین خطر اپ‌های سینک‌دار اینه که دستگاه دوم، دیتای دستگاه اول رو پاک کنه. اینجا این اتفاق نمی‌افته:

</div>

<div dir="ltr" align="center">

```
        ┌──────────────────────────────────────────────┐
        │              new / edited record             │
        └───────────────────────┬──────────────────────┘
                                │  saved locally, instantly
                                ▼
        ┌──────────────────────────────────────────────┐
        │              wait ~0.7s (debounce)           │
        └───────────────────────┬──────────────────────┘
                                ▼
   1  PULL     ───────▶   read the whole Gist
                                │
   2  BACKUP   ───────▶   cloud + local snapshot   (first run only)
                                │
   3  MERGE    ───────▶   per-record merge by _updatedAt
                                │                  + deletion tombstones
                                ▼
   4  DIFF?    ───────▶   anything changed?  ── no ──▶  STOP  (0 writes)
                                │ yes
                                ▼
   5  PUSH     ───────▶   write sport-data.json + this device shard
                                │
   6  VERIFY   ───────▶   read back and confirm            ✅
```

</div>

<div dir="rtl" align="right">

### فایل‌هایی که توی Gist ساخته می‌شن

| فایل | نقش |
|---|---|
| `sport-data.json` | نسخه‌ی اصلی و تلفیق‌شده — منبع حقیقت |
| `sport-device-<id>.json` | کپی مستقل هر دستگاه، به‌عنوان بیمه‌ی اضافی |
| `sport-migration-backup-*.json` | عکس دقیق دیتای Gist **قبل از** اولین نوشتن نسخه‌ی جدید |
| `sport-local-before-*.json` | عکس دیتای محلی هر دستگاه قبل از اولین تلفیق |
| `sport-snapshot-<time>.json` | بکاپ دستی، هر وقت خودت دکمه‌ش رو بزنی |

یعنی حتی اگه بدترین اتفاق بیفته، نسخه‌ی قبلی دیتات هنوز سالم توی Gist هست و برمی‌گردونیش.

### مصرف API گیت‌هاب

سقف گیت‌هاب برای توکن شخصی **۵۰۰۰ درخواست در ساعت** است ([مستندات رسمی](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)). مصرف واقعی این اپ:

| سناریو | تعداد درخواست |
|---|:---:|
| بررسی دوره‌ای وقتی دیتا عوض نشده | **۱** — فقط خواندن |
| بعد از ثبت یک رکورد | **۳** — خواندن، نوشتن، تأیید |
| تست اتصال | **۱** — فقط خواندن |
| فاصله‌ی بررسی خودکار | هر **۱۵ دقیقه** |

اپ سهمیه‌ی باقی‌مانده رو از هدرهای پاسخ می‌خونه و اگه از **۲۵** کمتر بشه، سینک خودکار رو تا شارژ دوباره‌ی سهمیه موقتاً متوقف می‌کنه. با استفاده‌ی روزمره حتی به دو درصد سقف هم نمی‌رسی.

<a id="security"></a>

## 🔒 امنیت

| لایه | جزئیات |
|---|---|
| **Content-Security-Policy** | `default-src 'none'` به‌علاوه‌ی هش SHA-256 برای تک‌تک اسکریپت‌ها · `object-src 'none'` · `base-uri 'none'` |
| **بدون inline handler** | هیچ `onclick` یا `onerror`ی توی HTML نیست — همه‌چیز با `addEventListener` بسته می‌شه |
| **ضد XSS** | تمام ورودی‌های کاربر — یادداشت، نام فعالیت، برچسب خواب — قبل از نمایش escape می‌شن |
| **رمز عبور** | PBKDF2-SHA256 با ۲۱۰٬۰۰۰ تکرار و salt تصادفی · هرگز به شکل خام ذخیره نمی‌شه |
| **CSV امن** | سلول‌هایی که با `=` یا `+` یا `-` یا `@` شروع بشن خنثی می‌شن تا توی اکسل اجرا نشن |
| **دامنه‌های مجاز** | فقط `api.github.com` و `gist.githubusercontent.com` اجازه‌ی اتصال دارن |
| **توکن** | فقط داخل `localStorage` مرورگر خودت · هیچ‌جا لاگ یا ارسال نمی‌شه |

> ⚠️ **حواست باشه:** این اپ برای **استفاده‌ی شخصی** ساخته شده. رمز عبور جلوی چشم فضول رو می‌گیره، ولی کسی که دسترسی فیزیکی به دستگاهت داشته باشه می‌تونه `localStorage` رو بخونه. برای دیتای واقعاً حساس ازش استفاده نکن.

## 🔧 عیب‌یابی

<details>
<summary><b>🔑 رمزم یادم رفته</b></summary>

<br>

کنسول مرورگر رو باز کن — روی دسکتاپ با `F12` — و این رو بزن:

<div dir="ltr" align="left">

```javascript
localStorage.removeItem('sport_auth_v1');
localStorage.removeItem('sport_session_v1');
location.reload();
```

</div>

فقط رمز پاک می‌شه و **دیتات دست نمی‌خوره**. دفعه‌ی بعد ازت رمز جدید می‌خواد.

</details>

<details>
<summary><b>☁️ سینک کار نمی‌کنه</b></summary>

<br>

به ترتیب چک کن:

۱. اول **تست اتصال** رو توی تنظیمات بزن و متن خطا رو بخون
۲. توکنت scope `gist` داره؟ نه `repo`، نه چیز دیگه — فقط `gist`
۳. Gist ID درسته؟ فقط همون رشته‌ی هگز، بدون نام کاربری و بدون اسلش
۴. توکن منقضی نشده؟ از [صفحه‌ی Tokens](https://github.com/settings/tokens) چک کن
۵. اگه نوشته سهمیه تموم شده، تا شروع ساعت بعدی صبر کن

</details>

<details>
<summary><b>📉 انگار یه رکورد گم شده</b></summary>

<br>

نفس عمیق بکش، تقریباً همیشه سالمه:

۱. برو به Gist خودت توی [gist.github.com](https://gist.github.com)
۲. فایل‌های `sport-migration-backup-*.json` یا `sport-device-*.json` رو باز کن
۳. محتواشون رو کپی کن و توی اپ از بخش **📥 وارد کردن** برگردون
۴. خود Gist هم تب **Revisions** داره — تاریخچه‌ی کامل تک‌تک تغییرها اونجاست

</details>

<details>
<summary><b>🔄 نسخه‌ی جدید رو نمی‌بینم</b></summary>

<br>

کش مرورگره. یکی از اینا رو امتحان کن:

- آدرس رو با یه پارامتر اضافه باز کن، مثل `?v=2`
- روی دسکتاپ `Ctrl+Shift+R` بزن
- روی اندروید: تنظیمات کروم ← حریم خصوصی ← پاک کردن داده‌های مرور ← فقط «تصاویر و فایل‌های ذخیره‌شده»

</details>

<details>
<summary><b>🩺 چطور از سلامت اپ مطمئن بشم</b></summary>

<br>

توی تنظیمات دکمه‌ی **🩺 بررسی سلامت** هست که گزارش کامل می‌ده. یا از کنسول:

<div dir="ltr" align="left">

```javascript
window._app.runHealthCheck()                    // full report
console.log(window._app.state().rows.length)    // number of records
```

## 🇬🇧 In English

**Sport Report** is a single-file personal tracker for exercise, sleep and energy, built around the Persian (Jalali) calendar.

The entire application lives in one `index.html` — no build step, no npm, no backend, no framework. Chart.js and the Jalali date library are embedded directly in the file, so it runs fully offline. Data is stored locally in your browser and can optionally sync to a **private GitHub Gist that you own**, using your own token, with no third-party server in between.

**Highlights**

| | |
|---|---|
| 🗓️ | Native Jalali calendar with correct leap-year handling |
| 😴 | Multi-block sleep tracking — naps and split sleep supported |
| 📊 | 8 interactive charts with 14 / 30 / 90 / all-time ranges |
| 🧠 | Readiness score weighted by data freshness, with a confidence rating |
| ☁️ | Conflict-safe sync — pull, merge, push, verify — with per-device shards, deletion tombstones and automatic pre-write backups |
| 🔒 | Strict CSP with per-script hashes, zero inline handlers, PBKDF2-SHA256 password hashing at 210k iterations |
| 📱 | Mobile-first RTL interface, responsive from 320px |
| 🎨 | 5 themes and 4 Persian fonts — charts follow the active palette |

**Try it:** [abbasahmadizade.github.io/my-sport-reports-only](https://abbasahmadizade.github.io/my-sport-reports-only/)

Fork it, enable GitHub Pages on `main` / root, and it is live. The interface is entirely in Persian.

Built with AI assistance on [**Arena.ai**](https://arena.ai) — huge thanks to their team for making solo projects like this genuinely possible. 💜
